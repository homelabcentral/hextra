{{/* Cover for a post card or a post hero. Renders nothing when the page has no cover, so there is no placeholder and no layout shift. The image is decorative — the post title always sits next to it — so `alt` is intentionally empty. A post can put a command there instead of a picture by setting `coverText`, in which case none of the image machinery below runs: there is no file to resolve, process or measure. A `cover` or `featured_image` in the post's own front matter beats it, so a `coverText` set across a section by `cascade` fills in only the posts that named no picture of their own. Only those two keys count - a bundle image merely named `cover.png` does not, because it is a convention the post never states, and it would then silently outrank a key the post does state. A key that names nothing loses too: with a text cover to fall back on, the image is resolved with `verify`, so `cover: iamges/hero.png` gives the command rather than a broken ``. Only a relative name can be checked - see `utils/page-image.html`. When the resolver returns an `lqip`, it is handed to the stylesheet as `--hextra-lqip` and painted as the image's own background, so a blurred stand-in shows until the real pixels land on top of it; `assets/js/core/lqip.js` then removes it, which is what keeps a cover with transparent edges from wearing a permanent blurred fringe. Covers without one (remote URLs, SVGs) simply fall back to the flat column background. Callers reach this through `partialCached`, keyed on the post's RelPermalink and the variant: the output depends on nothing else, and a list page renders the same post's card on /blog/, its tag pages and its series page. A `coverText` post is the expensive case - each line is a separate `highlight` call. @param {page} page The post. @param {string} [variant] "card" (default) or "hero". @example {{ partial "blog/cover.html" (dict "page" . "variant" "hero") }} */}} {{- $hero := eq (.variant | default "card") "hero" -}} {{- $text := .page.Params.coverText -}} {{- $named := or .page.Params.cover .page.Params.featured_image -}} {{/* Skipped entirely when a text cover has already won, so a post that names no picture still costs nothing: no file to resolve, process or measure. */}} {{- $cover := dict -}} {{- if or $named (not $text) -}} {{- $verify := false -}} {{- if and $named $text -}} {{- $verify = true -}} {{- end -}} {{/* One width for both variants. A card is not a thumbnail: it stretches to the full content column, which reaches ~672px, and every display worth optimising for is 2x or 3x - a 390px phone at DPR 3 wants ~1170 device pixels, a 672px card at DPR 2 wants ~1344. The 800px copy this used to emit was upscaled by the browser in both cases, which is what turned screenshot text to mush. Sharing the spec with the hero also means one processed file per cover instead of two. */}} {{- $process := "Resize 1600x webp q80" -}} {{- $cover = partial "utils/page-image.html" (dict "page" .page "process" $process "verify" $verify) -}} {{- end -}} {{- with $cover.url -}} {{- $lazyLoading := site.Params.enableImageLazyLoading | default true -}} {{- else -}} {{- with $text -}} {{- partial "components/command-block.html" (dict "lines" . "mode" "cover" "class" (cond $hero "hextra-command--hero" "")) -}} {{- end -}} {{- end -}}
